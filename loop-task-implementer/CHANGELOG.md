# loop-task-implementer changelog

For earlier history, see the `## loop-task-implementer` section in the repository root `CHANGELOG.md`.

## v1.2 — post-merge Batch 5.2C lifecycle hardening (2026-08-21)

- Made `scripts/validate_loop_lifecycle.py` an actual fail-closed CLI. The documented `python ... --state <state.json>` lifecycle gate now reads official JSON state and exits `0` only on a valid state, `1` on lifecycle errors, and `2` whenever argument/input/runtime validation cannot complete. This closes the original function-only direct-execution no-op, unexpected runtime exceptions, imported-runtime `SystemExit(0)`, and argparse success exits such as `--help`, none of which may count as lifecycle proof.
- Bound third-party branch-change evidence to the exact current head with `workspace.third_party_change_checked_head`, and changed the default detection state from `false` to `null` so unrefreshed state cannot masquerade as a clean branch check.
- Bound degraded-isolation human exceptions to the exact `reviewed_change_identity`; stale authorization from an earlier review identity no longer carries forward after evidence is invalidated or rerun. An `ISOLATED` review must also have all exception fields cleared, including stale provenance.
- Aligned `reference/phase-index.md` with the canonical `SKILL.md` review/remediation order and made the mandatory lifecycle overlay explicitly authoritative wherever legacy readiness/completion text conflicts with it.
- Made the shared lifecycle contract portable in both source and installed packages. `review-lifecycle-contract.yaml` now stores shared contract paths relative to the repository/package root, while `workflow/reviewer-evidence.md` uses normal source-tree Markdown links that the existing packager rewrites to vendored package-local links. The lifecycle gate and Orchestrator overlay now resolve the validator from the actual directory containing the skill's `SKILL.md` instead of assuming the current working directory is the software-builder checkout, so installed execution from a target repository reaches the packaged validator correctly. Tests package the skill and verify the shared contracts/runtime resolve inside the installed bundle.
- Corrected completion-report safe output: human-entered isolation-exception provenance is escaped/redacted free text, and the report projects only the validated head SHA plus normalized fingerprint from `isolation_exception_change_identity` instead of inline-rendering the entire identity object, whose path/config/dependency fields may contain attacker-shapeable text. The escalation machine-state block now uses Rule 4's dynamically sized outer backtick fence rather than a fixed triple-backtick YAML fence, preventing nested task/repository strings from closing the fence and forging live Markdown.
- Aligned setup metadata with the platform-neutral contract: the skill has repo-specific Git-provider/API and CI-provider dependencies, not a fixed GitLab MCP dependency; `scripts/registry/setup_freshness.yaml` and `SETUP.md` now agree.
- Workflow frontmatter now tracks the remediation generation: `reviewer-evidence` remains `1.4`, while the subsequently changed validator-invocation paths in `orchestrator-lifecycle` and `lifecycle-gate` are `1.5`. `reference/state-schema.yaml` remains workflow version `1.4`; skill version is `1.2`.
- Expanded regression coverage for CLI exit semantics, stale/missing third-party check heads, isolation-exception identity/provenance hygiene, canonical review ordering, source/install shared-contract and validator-path portability, workflow-version alignment, and safe report rendering including the escalation fence.
